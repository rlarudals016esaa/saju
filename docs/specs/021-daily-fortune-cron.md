# 021 · Vercel Cron 오늘의 운세 사전 생성

## 목적

로그인한 사용자가 아침에 기다리지 않고 오늘의 운세를 확인할 수 있도록, 사용자별 가장 최근 사주 1건을 기준으로 매일 운세를 미리 생성합니다. 운세는 자기 성찰을 위한 참고이며 미래 사건을 확정하지 않습니다.

## 사용자 경험

1. 사용자는 한국 시간 오전 7시 이후 오늘의 운세 화면에서 미리 생성된 운세를 확인합니다.
2. 운세는 종합운·일/학업운·금전운·관계운·오늘의 행동으로 구성합니다.
3. 사용자별 가장 최근에 저장된 사주 1건만 기준으로 사용합니다. 과거 이력의 모든 사주마다 운세를 만들지 않습니다.
4. 최근 저장 사주가 없으면 먼저 사주 해석을 만들도록 안내합니다.
5. 최근 30일의 운세만 조회할 수 있습니다.
6. 예약 생성이 실패한 사용자는 화면에 방문했을 때 그날 운세 생성을 다시 시도할 수 있습니다.
7. 생년월일 입력과 사주 생성 뒤에도 사주 페이지에서 결과를 확인할 수 있습니다. 사주 페이지 우측 하단에는 문서 흐름을 밀어내지 않는 오늘의 운세 플로팅 배너를 표시하고, 클릭하면 별도의 오늘의 운세 화면으로 이동합니다.
8. 사주 페이지의 플로팅 배너를 클릭해 오늘의 운세 화면에 들어오면 운세를 즉시 조회하고, 오늘 결과가 없으면 생성합니다. 오늘의 운세 화면에는 다시 눌러야 하는 두 번째 캐릭터 배너를 표시하지 않습니다. 사주 페이지의 플로팅 배너는 키보드와 스크린 리더에서 목적을 알 수 있어야 하며 모바일 화면과 모션 감소 설정을 지원합니다.

## 예약 실행

- Vercel Hobby Cron을 사용해 매일 `21:00 UTC`에 실행합니다. Hobby의 시간 단위 실행 오차를 고려하면 한국 시간 오전 6시부터 6시 59분 사이에 호출되며, 오전 7시까지 준비 완료를 목표로 합니다.
- Cron은 프로덕션 배포의 고정 Route Handler에 GET 요청을 보냅니다.
- 엔드포인트는 Vercel 환경변수 `CRON_SECRET`과 `Authorization: Bearer ...` 헤더가 정확히 일치할 때만 실행합니다. 비밀값은 코드·Git·응답·로그에 남기지 않습니다.
- Vercel은 실패한 Cron을 자동 재시도하지 않으므로 실행 결과에 대상·성공·실패·건너뜀 수를 남기고, 개별 실패가 다음 사용자의 처리를 막지 않게 합니다.
- Cron이 중복 전달되거나 이전 실행과 겹칠 수 있으므로 데이터베이스 고유 제약과 상태 확인으로 멱등성을 보장합니다.

## 계산과 AI 역할

- 사용자별 대상 사주는 `saju_readings`의 가장 최근 저장 결과 1건입니다.
- 한국 표준시 기준 운세 날짜와 오늘의 간지는 앱의 결정적 계산 코드가 만듭니다. Gemini에게 사주나 날짜 간지를 계산하게 하지 않습니다.
- Gemini에는 검증된 사주 계산 요약과 오늘의 간지만 전달합니다. 원본 생년월일·출생시간, 사용자 계정 정보와 다른 사용자의 자료는 전달하지 않습니다.
- Gemini는 종합운·일/학업운·금전운·관계운·오늘의 행동을 한국어로 작성합니다.
- 서버는 필수 항목, 문자열 길이, 빈 값과 금지 표현을 검사한 결과만 저장합니다. 질병·법률·재산·수익·합격·결혼·이별 등 미래 사건을 확정하거나 특정 투자·대출을 권하는 문장은 거절합니다.

## 저장과 보관

- 오늘의 운세에는 사용자 ID, 기준 사주 ID, 한국 날짜, 검증된 운세, 생성 상태와 생성 시각을 저장합니다.
- 사용자 ID와 한국 날짜 조합을 고유하게 만들어 같은 날 한 사용자에게 결과가 중복 생성되지 않게 합니다.
- 사용자는 자신의 운세만 조회할 수 있도록 행 수준 접근 정책을 적용합니다. Cron의 서버 전용 권한은 브라우저에 노출하지 않습니다.
- 최근 30일 결과만 보관하고 더 오래된 결과는 예약 실행 과정에서 삭제합니다.
- 원본 출생일시, Gemini API 키, Google 인증 토큰과 사용자 이메일은 오늘의 운세에 저장하지 않습니다.

## 규모와 실패 처리

- Hobby Function 실행 시간 안에 끝나도록 사용자를 작은 묶음으로 처리합니다.
- 사용자 한 명의 Gemini 또는 저장 실패는 기록한 뒤 나머지 사용자를 계속 처리합니다.
- 같은 날 결과가 이미 있으면 Gemini를 다시 호출하지 않고 건너뜁니다.
- 사용자가 방문했는데 오늘 결과가 없으면 해당 사용자만 동일한 생성 로직으로 다시 시도합니다.
- 대상 사용자 수가 한 번의 Hobby 실행 한도를 안정적으로 넘으면 Pro 플랜 또는 지속성 있는 작업 큐로 이전합니다. 조용히 일부 사용자만 제외하지 않습니다.

## 제외할 것

- 저장된 모든 과거 사주별 운세 생성.
- 매시간 또는 실시간으로 달라지는 운세.
- 운세 푸시 알림, 이메일 발송과 공개 공유.
- Gemini를 이용한 사주·간지 계산과 확정적인 미래 예측.
- 30일보다 오래된 운세 보관.

## 확인 기준

- 한국 날짜가 바뀐 뒤 오전 7시까지 대상 사용자별 오늘 운세가 한 건씩 준비됩니다.
- 가장 최근 사주만 기준으로 사용되고, 최근 사주가 없는 사용자는 안전하게 제외됩니다.
- 같은 Cron 또는 화면 재시도가 중복 실행되어도 운세와 Gemini 호출이 중복되지 않습니다.
- 잘못된 `CRON_SECRET` 요청은 작업 전에 401로 거절됩니다.
- 일부 사용자 생성 실패에도 나머지 사용자가 처리되고 실패 수가 관찰 가능합니다.
- 방문 시 재시도가 예약 실패를 보완하며, 실패를 가짜 운세로 바꾸지 않습니다.
- 다른 사용자의 운세를 조회할 수 없고 30일이 지난 운세가 정리됩니다.
- 기존 사주 생성·이력·공유 기능과 전체 자동 시험, 타입 검사, 프로덕션 빌드가 통과합니다.

## 검증 기록

- 2026-09-28: 한국 날짜·간지 계산, Gemini 구조화 응답과 금지 표현 검사, 사용자·날짜별 원자적 선점, 최근 사주 선택, 30일 보관, 방문 시 재시도, 로그인 전 차단과 오늘·과거 운세 화면을 구현했습니다.
- Vercel Cron 경로는 `CRON_SECRET` Bearer 인증 뒤에만 실행되며, 매일 `21:00 UTC` 일정과 사용자별 실패 격리·실행 집계를 추가했습니다. 관리자 키는 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`로만 읽습니다.
- 구현을 맡지 않은 독립 담당이 오늘의 운세와 플로팅 배너 시험을 추가·보강했습니다. 최종 `npm run check`에서 TypeScript 검사와 전체 자동 시험 132개가 통과했고, `npm run build`에서 `/daily-fortune`, `/api/daily-fortunes`, `/api/cron/daily-fortunes`를 포함한 프로덕션 빌드가 성공했습니다. 사주 결과 유지, 우측 하단 플로팅 링크, 운세 페이지 진입 즉시 조회·누락 시 생성, 중복 배너 제거, 키보드 포커스·스크린 리더 이름·모바일 안전 여백과 모션 감소 설정도 확인했습니다.
- 실제 Supabase 프로젝트에는 새 마이그레이션을 적용하지 않았고 Vercel Production 환경변수·Cron 실행도 확인하지 않았습니다. 따라서 `docs/status.md`는 완료로 바꾸지 않습니다.
