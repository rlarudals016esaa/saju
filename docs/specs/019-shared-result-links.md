# 019 · 결과 공유 링크

## 목적

로그인한 사용자가 저장된 사주 결과를 전용 링크로 공유하고, 링크를 받은 사람은 로그인 없이 결과를 읽을 수 있게 합니다. 공유받은 사람이 자신의 사주를 생성하는 흐름은 기존 Google 로그인을 그대로 거칩니다.

## 동작

1. 새로 생성해 계정에 저장된 결과와 저장 이력의 상세 결과에 `결과 공유하기` 버튼을 표시합니다. 저장에 실패한 일시적 결과에는 공유 버튼을 표시하지 않습니다.
2. 사용자가 버튼을 누르면 해당 계정 소유의 결과인지 서버에서 확인한 뒤, 결과별로 고정된 무작위 UUID 토큰을 만듭니다. 같은 결과를 다시 공유하면 같은 링크를 돌려줍니다.
3. 지원하는 기기에서는 시스템 공유 화면을 열고, 그렇지 않으면 링크를 클립보드에 복사합니다. 자동 공유나 복사가 불가능하면 사용자가 직접 복사할 수 있는 링크를 화면에 표시합니다.
4. `/share/[token]`은 로그인 없이 열립니다. 공유된 성향·강점·살펴볼 점, 운의 흐름, 오행 분포, 다섯 분야 조언, 계산 상세와 관계 유형을 읽기 전용으로 보여줍니다.
5. 공유 화면의 `내 사주 보러 가기`는 `/`로 연결합니다. 비로그인 방문자는 Google 로그인 화면을 보고, 이미 로그인한 방문자는 기존 `/reading`으로 이동합니다.
6. 공유 자료에는 계산 결과와 검증된 AI 해석, 결과 생성 시각만 포함합니다. 출생일시 원문, 사용자 ID·이메일, 인증 정보와 API 키는 공개 응답과 화면에 포함하지 않습니다.
7. 원본 저장 결과를 삭제하면 연결된 공유 자료도 함께 삭제되어 기존 링크는 찾을 수 없는 결과로 표시됩니다.

## 보안과 데이터 구조

- `saju_reading_shares`에 공개용 스냅샷과 무작위 토큰을 저장합니다. 원본 결과 한 건당 공유 행은 하나만 둡니다.
- 테이블 자체는 익명·로그인 클라이언트 모두 직접 조회할 수 없게 유지합니다.
- 공유 생성 함수는 현재 로그인한 사용자가 소유한 결과만 복사합니다. 공개 조회 함수는 정확한 토큰 한 건만 반환하며 목록 조회 기능은 제공하지 않습니다.
- 토큰 형식이 잘못됐거나 존재하지 않는 경우 결과의 존재 여부나 계정 정보를 추가로 노출하지 않고 찾을 수 없음으로 처리합니다.

## 확인 기준

- 비로그인 사용자는 공유 생성 API를 사용할 수 없고, 다른 계정 결과의 공유 링크를 만들 수 없습니다.
- 링크를 받은 비로그인 사용자는 공유 결과를 볼 수 있으며, 자신의 사주 보기 동선에서는 로그인을 요구받습니다.
- 공유 응답과 화면에 출생일시 원문·소유자 식별 정보가 없습니다.
- 같은 결과를 여러 번 공유해도 링크가 늘어나지 않고, 원본 삭제 뒤 공개 조회가 되지 않습니다.
- 잘못된 토큰·없는 토큰·DB 오류를 성공으로 표시하지 않습니다.
- 기존 로그인·결과 생성·이력·삭제 기능과 자동 시험, 타입 검사, 배포용 빌드가 통과합니다.

## 검증 기록

- 2026-09-23: 저장 결과별 고정 UUID 공유 토큰, 소유자만 호출하는 공유 생성 함수, 토큰 한 건만 반환하는 공개 조회 함수와 `/share/[token]` 읽기 전용 화면을 구현했습니다. 새 결과와 이력 상세의 저장된 결과에 공유 버튼을 추가했고, 공개 화면의 `내 사주 보러 가기`는 기존 로그인 진입점 `/`로 연결했습니다.
- 독립 검증 담당이 인증·소유권·토큰 오류·DB 오류·민감정보 비노출·SQL 함수 권한·원본 삭제 cascade·양쪽 공유 버튼과 시스템 공유/클립보드 대체 동작을 확인하는 시험 8개를 추가했습니다. 최종 `npm run check`에서 TypeScript 검사와 자동 시험 104개가 모두 통과했고 `npm run build`도 성공했습니다.
- 공유용 데이터베이스 마이그레이션은 파일로 작성했지만 연결된 Supabase 프로젝트에는 적용하지 않았습니다. 실제 비로그인 브라우저에서 생성된 공유 링크를 여는 검증은 마이그레이션 적용 후 진행해야 하므로 상태 체크는 보류합니다.
