# 009 · 로그인 후 생년월일 입력 화면 이동

## 목적

첫 화면에서는 Google 로그인에 집중하고, 로그인에 성공한 다음 별도의 생년월일 입력 화면으로 이동합니다.

## 사용자 흐름

1. 로그인하지 않은 사용자가 `/`에 방문하면 서비스 소개와 `Google로 로그인` 버튼만 봅니다. 생년월일 입력란과 개인 이력은 보이지 않습니다.
2. Google 인증이 성공하면 앱의 고정된 `/reading` 경로로 이동합니다. 이미 로그인한 사용자가 `/`에 오면 같은 경로로 이동합니다. 이 화면에는 `언제 태어나셨나요?`와 날짜·시간 입력 및 새로 생성한 결과만 표시하고, 로그인 상태·저장 이력 목록·로그아웃 도구를 함께 표시하지 않습니다.
3. 로그인하지 않은 사용자가 `/reading`에 직접 접근하면 `/`로 돌아갑니다. 해석 API의 서버 인증은 그대로 유지합니다.
4. 저장된 이력은 별도의 `/history` 화면에서 열람·삭제하고, 그곳에서 로그아웃하면 개인 화면 상태를 비우고 `/`로 돌아갑니다. 취소·실패한 로그인은 `/`에서 안내하고 다시 시도할 수 있습니다.

## 확인 기준

- 익명 사용자에게 `/`은 로그인 화면이고 `/reading`은 접근할 수 없습니다.
- 인증 후에는 생년월일 입력 화면이 나타나며, 다시 `/`에 와도 입력 화면으로 이동합니다.
- 실패한 OAuth는 입력 화면으로 이동하지 않고 로그인 화면에 이유를 보여줍니다.
- 기존 결과 이력, 배경, 해석 기능은 유지됩니다. `/history`도 서버에서 로그인 여부를 확인합니다.

## 검증 기록

- 2026-09-23: `/`을 로그인 전용 화면으로, `/reading`을 서버 인증이 필요한 생년월일 입력·결과 화면으로 분리했습니다. 인증 콜백 성공 시 `/reading`, 취소·실패 시 `/`로 이동하도록 변경했습니다.
- 전체 자동 시험 49개, TypeScript 검사, 배포용 빌드가 통과했습니다. 익명 HTTP 접속에서 `/`은 200이며 로그인 문구는 있고 날짜 입력란은 없었습니다. `/reading`은 307로 `/`에 이동했습니다.
- 사용자 화면 피드백을 반영해 `/reading`의 상단 로그인 상태·이력 영역을 입력 카드에서 제거했습니다. 처음에는 아래로 옮겼으나, 여전히 같은 페이지에 남는다는 점을 확인해 `/history` 별도 화면으로 완전히 분리했습니다. 마지막 구조에 대한 자동 시험과 빌드는 아래에 추가 기록합니다.
