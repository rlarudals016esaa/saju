# 024 · 생일 입력 후 오늘의 운세

> 후속 Spec 027에서 이 화면의 생일 재입력 폼은 제거하고, 사주 해석에 입력한 생일을 배너 클릭 시 한 번 전달하는 방식으로 변경했습니다.

## 목적

사용자가 양력 생년월일을 직접 입력하고 요청한 뒤에만 오늘의 운세를 표시합니다. 근거가 없는 자동 운세처럼 보이지 않게 합니다.

## 동작

1. 로그인한 사용자가 `/daily-fortune`에 들어오면 날짜 입력칸과 `오늘의 운세 보기` 버튼만 보입니다. 운세 API를 자동으로 호출하거나 기존 저장 사주를 몰래 선택하지 않습니다.
2. 유효한 양력 생년월일을 제출하면 서버에서 기존 사주 계산기로 출생시간 미상·시주 제외 계산을 수행하고, 한국 기준 오늘의 간지와 조합해 운세를 돌려줍니다.
3. 결과에 입력한 생년월일을 계산 기준으로 표시합니다. 날짜를 바꾸면 이전 결과를 숨깁니다.
4. 생년월일 원문과 오늘의 운세는 데이터베이스나 브라우저 저장소에 저장하지 않습니다. Gemini도 호출하지 않습니다.
5. 출생시간이 없어 세 기둥만 사용한 간단한 참고이며 실제 사건을 예측하는 결과가 아님을 안내합니다.

## 확인 기준

- 입력 전과 날짜 변경 직후에는 운세가 보이지 않고 API도 호출되지 않습니다.
- 유효한 생년월일을 제출하면 그 날짜로 계산한 결과가 표시됩니다.
- 누락·유효하지 않은 날짜와 비로그인 요청은 운세 계산 전에 거절됩니다.
- 기존 사주 해석과 저장 이력은 그대로 동작합니다.
- 자동 시험, 타입 검사, 빌드가 통과합니다.

## 검증 기록

- 독립 검증 담당이 입력 전 결과·자동 API 호출 차단, 제출 날짜 POST, 날짜 변경 시 이전 결과 숨김, 비로그인·잘못된 날짜 차단, 날짜별 결과 차이와 DB 미접근·비저장을 시험했습니다. 관련 시험 10개가 통과했습니다.
- 최종 `npm run check`: TypeScript 검사와 자동 시험 129개 통과. `npm run build`: 성공.
- 로그인된 로컬 화면에서 최초에 생년월일 입력칸만 보이고, 테스트 날짜 `2000-01-01`을 제출한 뒤에만 입력 생일·오늘 날짜와 운세가 표시되는 것을 확인했습니다. 입력을 `1993-07-18`로 바꾸자 이전 결과가 즉시 사라졌습니다.
- 참가자가 자신의 생일로 확인한 것은 아직 아닙니다.
