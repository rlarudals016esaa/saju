# 007 · Google 로그인

## 목적

사용자가 Google 계정으로 로그인한 뒤에만 개인 사주 해석을 요청하고, 자신의 결과 이력에 접근하게 합니다. 로그인은 Supabase Auth의 Google 제공자를 사용합니다. Codex가 Supabase MCP에 로그인한 것과 서비스 이용자의 Google 로그인은 별개입니다.

## 확정한 범위

- 참가자 선택: **로그인해야 사주 해석 가능**.
- 로그인하지 않은 사람은 소개·입력 안내를 볼 수 있지만 Gemini 해석 생성과 저장 결과 열람은 할 수 없습니다.
- Google 로그인과 로그아웃만 제공합니다. 이메일·비밀번호 가입, 다른 소셜 로그인, Google 연락처·캘린더 접근은 제외합니다.

## 사용자 흐름

1. 처음 방문하면 로그인 전용 화면에서 `Google로 로그인` 버튼과 로그인해야 해석을 이용할 수 있다는 안내를 보여줍니다. 생년월일 입력 화면은 별도 경로입니다(Spec 009).
2. 버튼을 누르면 Supabase Auth의 Google OAuth 인증 화면으로 이동합니다. 사용자가 동의를 취소하거나 인증이 실패하면 원래 화면에서 이유와 재시도 수단을 보여줍니다.
3. 인증 후 허용된 앱의 콜백 경로에서 인증 코드를 세션으로 교환하고, 앱 내부의 `/reading` 생년월일 입력 화면으로 이동합니다. 임의 외부 주소로 보내는 리디렉션은 허용하지 않습니다.
4. 세션이 유효할 때만 입력 폼의 해석 제출을 활성화합니다. 새로고침 후에도 로그인 상태를 복원하고, 세션이 만료되면 다시 로그인하도록 안내합니다.
5. 로그아웃하면 세션을 끝내고 개인 해석·이력 화면을 숨깁니다. 공용 브라우저에서 다른 계정으로 바뀔 때 이전 계정 결과가 남아 보이지 않게 화면 상태를 비웁니다.

## 구조와 보안

- 기존 Next.js App Router와 Supabase Auth를 연결합니다. 서버 렌더링과 API 경로에서 세션을 확인할 수 있도록 Supabase의 서버 측 인증 흐름을 사용합니다.
- Google 제공자 설정에는 Google Cloud의 OAuth Client ID·Secret, 허용된 앱 출처, Supabase 콜백 주소, 개발·배포 환경의 앱 리디렉션 주소가 필요합니다. Secret은 Supabase 설정에 보관하고 Git·브라우저 코드에 넣지 않습니다.
- 앱 설정에는 기존 `.env.example`의 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 사용합니다. 공개 가능한 키여도 데이터 접근 권한을 주는 비밀키처럼 취급하지 말고, 실제 보호는 사용자 인증과 데이터베이스 정책으로 합니다. 서비스 역할 키는 브라우저에 두지 않습니다.
- `/api/reading`은 **Gemini 호출 전에** 서버에서 현재 사용자를 확인합니다. 로그인하지 않았거나 세션이 만료되면 401로 거절합니다. 브라우저가 보낸 `user_id`는 신뢰하지 않습니다.
- Google 계정의 추가 권한은 요청하지 않습니다. Google 제공자 토큰이나 프로필 전체는 결과 저장소에 기록하지 않습니다.
- 기존 Spec 006의 익명 `localStorage` 결과는 로그인 계정의 데이터베이스에 자동으로 올리지 않습니다. 계정 변경·로그아웃 시 이전 결과를 화면에 재사용하지 않습니다. 브라우저 저장 기능의 제거 또는 계정별 분리는 Spec 008 구현 전에 함께 정리합니다.

## 확인 기준

- 로그인 전에는 생년월일 입력 화면에 접근할 수 없고, 직접 `/api/reading`을 호출해도 Gemini 요청 전에 401을 받습니다.
- 실제 Google 로그인 후 콜백·세션 복원·로그아웃이 동작합니다. 잘못된 콜백 코드, 취소, 만료된 세션, 외부 리디렉션 시도는 안전하게 처리합니다.
- 계정 A에서 로그아웃해 계정 B로 로그인할 때 A의 해석·이력은 보이지 않습니다.
- 공개 브라우저 번들, 응답, Git에 Google Client Secret·서비스 역할 키가 없습니다.
- 자동 시험은 인증 유무·계정 전환·API 보호를 검증하고, 실제 OAuth 왕복은 로컬과 배포 주소에서 사람이 확인합니다.

## 구현 전 필요한 참가자 설정

- Google Cloud와 Supabase 프로젝트에서 Google 제공자를 연결하고, 실제 사용할 개발·배포 주소를 허용 목록에 등록해야 합니다. 로그인과 동의 화면에서 참가자가 직접 확인할 단계입니다.
- 배포 주소가 아직 정해지지 않았다면 로컬 주소로 먼저 시험하고, 배포 전에 허용 주소를 다시 설정합니다.

## 검증 기록

- 2026-09-23: Supabase 서버·브라우저 클라이언트, 세션 갱신용 proxy, Google OAuth 콜백, 로그인·로그아웃 화면, 해석 API의 서버 인증을 구현했습니다.
- 전체 자동 시험 46개, TypeScript 검사, 배포용 빌드가 통과했습니다. 로그인하지 않은 상태에서 해석 API가 401을 반환하고 화면의 해석 입력이 비활성화됨을 로컬 서버에서 확인했습니다.
- Supabase 인증 설정에서 Google 제공자가 켜져 있는 것은 확인했으나, 실제 Google 계정으로 인증 화면을 왕복하고 로그아웃·세션 복원·계정 전환을 확인하지는 못했습니다. 따라서 완료 체크는 보류합니다.
