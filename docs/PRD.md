# 📋 기획서 (PRD) : 나의 사주 이해와 분야별 조언

> 무엇을, 왜, 어떻게 만들지 정리한 문서입니다. 이후 기능을 만들 때 기준으로 사용합니다.

작성일: 2026-09-23

최근 수정일: 2026-09-28

작성자: 서비스 기획자(참가자)

---

## 1. 풀고자 하는 문제

- **지금은 이렇게 해요 (현재 방식):** 현재 Starter 화면에 양력 생년월일과 출생시간을 입력하면 기본 사주 계산값(일주, 일간, 네 기둥)을 확인할 수 있습니다. 사용자가 지금 고민을 어떻게 풀고 있는지는 아직 확인하지 않았습니다.
- **이게 불편해요 (문제점):** 계산값만으로는 자신의 성향과 강점·약점이 무엇인지, 취업·연애·인간관계·삶의 흐름 고민에 어떻게 참고할지 이해하기 어렵습니다.
- **이렇게 되면 좋겠어요 (이상):** 결과 첫 화면에서 핵심 성향과 강점·약점을 한눈에 보고, 관심 있는 분야를 선택해 이해하기 쉬운 조언을 확인합니다.

---

## 2. 사용자

- **누가 쓰나요?** 취업, 연애, 인간관계 또는 전반적인 삶의 흐름을 고민하는 사람.
- **언제 쓰나요?** 해당 고민을 돌아보고 자기 이해를 위한 참고가 필요할 때 사용합니다. 오늘의 운세는 하루를 시작하는 아침에 확인합니다.
- **어디서 쓰나요?** 브라우저로 여는 사주 서비스. 실제 공개 범위와 배포 방식은 추후 결정합니다.

---

## 3. 입력 자료

- **사용할 파일 또는 입력 내용:** 현재 서비스가 받는 양력 생년월일과 출생시간, 그리고 이를 바탕으로 계산한 사주 결과.
- **반드시 필요한 항목:** 양력 생년월일. 출생시간을 알면 함께 입력하고, 모르면 `시간 모름`을 선택합니다. 시간 미상 결과는 시주를 제외하며 정확한 시간 정보가 없어 해석이 덜 세밀할 수 있음을 알립니다.
- **개인정보나 민감 정보 포함 여부:** 생년월일과 출생시간은 개인에 관한 정보입니다. 첫 구현에는 계정 생성이나 결과 저장을 넣지 않았습니다. 다음 단계인 Spec 006에서는 원본 입력 없이 가장 최근 결과 1건만 브라우저에 저장할 계획입니다.
- **아직 없는 자료:** 첫 구현은 일간의 오행을 기준으로 미리 검토한 안내 문구를 선택해 보여줍니다. 개인별 문장을 만드는 Gemini 연결은 Spec 006에서 계획합니다.
- **오늘의 운세 입력 자료:** 사용자별 가장 최근에 저장된 사주 계산 결과와 한국 표준시 기준 오늘 날짜의 간지입니다. 생년월일·출생시간 원문은 오늘의 운세 생성용 데이터로 다시 저장하지 않습니다.

## 4. 핵심 기능 (MVP) : 이것만 되면 일단 성공

1. 사용자가 양력 생년월일과 출생시간을 입력해 사주 계산 결과를 볼 수 있습니다. 시간을 모르면 `시간 모름`을 선택해 시주를 제외한 결과를 볼 수 있습니다.
2. 결과 첫 부분에 핵심 성향과 강점·약점을 짧고 읽기 쉽게 보여줍니다.
3. 취업, 연애, 인간관계, 전반적인 삶의 흐름을 각각 구분해 조언을 보여줍니다.
4. 사용자가 관심 있는 분야를 선택해 해당 조언을 자세히 읽을 수 있습니다.
5. 입력이 잘못되었거나 조언을 만들 수 없으면 이유를 알기 쉬운 문장으로 보여줍니다.
6. 목·화·토·금·수의 개수를 오각형 그래프와 숫자로 보여주고, 화면 기준으로 적은 편·보통·많은 편을 알려줍니다. 이 숫자만으로 실제 오행의 강약을 판단하지 않습니다.
7. 전년·올해·다음 해의 연간 오행 흐름을 배너로 보여주고, 맨 아래에서 일간 오행 기준으로 잘 맞을 수 있는 유형과 조율이 필요한 유형을 참고로 보여줍니다.
8. 로그인한 사용자는 저장된 결과의 전용 공유 링크를 만들 수 있고, 링크를 받은 사람은 로그인 없이 해당 결과를 볼 수 있습니다. 공유 화면에서 자신의 사주를 보려면 Google 로그인을 거칩니다.
9. 로그인한 사용자는 가장 최근에 저장한 사주 1건을 기준으로 매일 미리 생성된 오늘의 운세를 확인할 수 있습니다. 사주 페이지에서는 사주 결과를 그대로 읽을 수 있고, 화면 우측 하단의 플로팅 배너를 누르면 별도의 오늘의 운세 화면으로 이동해 운세를 즉시 조회하거나 생성합니다. 오늘의 운세 페이지에는 같은 기능을 반복하는 두 번째 배너 버튼을 두지 않습니다. 오늘의 운세는 종합운·일/학업운·금전운·관계운·오늘의 행동을 제공하며 최근 30일 동안 조회할 수 있습니다.

- **AI에게 맡길 것:** Gemini는 기존 코드가 계산한 사주와 오늘의 간지를 바탕으로 해석 문장만 작성합니다. 사주와 날짜의 간지 계산, 대상 사용자 선정, 중복 방지와 보관 기한 관리는 앱과 데이터베이스가 담당합니다.
- **사람이 확인할 것:** 사용자는 결과를 자기 이해의 참고로 보고, 중요한 취업·관계 결정은 직접 판단합니다. 제작 단계에서는 조언의 이해 가능성과 과도한 단정 표현을 사람이 확인합니다.

## 5. 결과와 완료 조건

- **결과물과 저장 위치:** `day09/`의 웹 화면. 기획서는 `day09/docs/PRD.md`에 둡니다.
- **어떤 입력이면 어떤 결과가 떠야 하는가:** 유효한 양력 생년월일과 출생시간을 입력하면 결과의 맨 앞에 성향·강점·약점 요약이 보이고, 전년·올해·내년 흐름 배너, 오행 개수 오각형, 분야별 조언과 맨 아래의 간단한 관계 유형을 읽을 수 있어야 합니다. `시간 모름`을 선택한 경우 시주와 시주의 오행은 제외하고 출생시간 미반영 및 정확도 한계를 명시합니다.
- **실패하면 무엇이 보여야 하는가:** 날짜나 시간이 비어 있거나 유효하지 않으면 해당 입력을 확인하라는 안내를 보여줍니다. 조언 생성에 실패하면 빈 결과나 꾸며낸 내용을 보여주지 않고 다시 시도할 수 있도록 안내합니다.
- **확인 방법:** 참가자가 화면에서 요약의 위치와 네 분야 조언의 존재를 직접 확인합니다. 조언 내용이 자신의 실제 삶과 일치하는지를 완료 판정 기준으로 삼지는 않습니다.

## 6. 나중에 추가할 것 (지금은 안 만듦)

- 첫 구현에서는 회원가입·로그인과 이전 결과 이력을 제외했습니다. 이후 Google 로그인과 계정별 결과 이력은 Spec 007·008의 다음 구현 단계로 계획합니다. 다른 로그인 방식은 계속 제외합니다.

- 결제와 유료 상담은 이번 범위에서 제외합니다. 이후 도입 여부도 미정입니다.

## 7. 만드는 방식과 공유 방법

- [ ] **일회성** : 한 번 또는 가끔 직접 돌리는 작업.
- [x] **자동화** : 사용자가 보지 않아도 자동으로 돌아야 하는 작업.
- [x] **도구·웹** : 사용자가 필요할 때 브라우저에서 여는 서비스.

선택: 기존 Next.js 웹 서비스를 이어서 개선합니다. 이미 입력 화면과 사주 계산 기능이 있으므로 그 위에 결과 설명 화면을 설계합니다.

**다 되면 어떻게 전달하나:** 먼저 로컬 브라우저에서 확인합니다. 다른 사람에게 공개할 인터넷 주소와 공개 범위는 별도로 결정합니다.

**화면 분위기:** 참가자가 선택한 별·초승달·산 능선의 밤하늘 이미지를 페이지 배경에 사용하고, 가운데 입력·결과 영역은 흰색 알파값 0.2의 반투명 박스로 표시합니다. 처음에는 0.5, 다음에는 0.35였으나 배경이 더 보이도록 조정했습니다. 글은 읽기 쉬운 대비로 유지합니다.

**링크 미리보기:** Spec 020에서 같은 밤하늘 배경을 바탕으로 서비스 제목이 들어간 공개용 이미지를 만들고, 카카오톡 등에서 사이트·결과 공유 링크에 공통으로 표시할 메타데이터에 연결합니다. 개인의 해석 내용은 미리보기에 넣지 않습니다.

## 다음 단계: 개인별 AI 해석

Spec 006에서 `gemini-3.5-flash-lite`로 성향·강점·주의할 점과 네 분야 조언을 생성하고, 성공한 최근 결과 1건을 브라우저 `localStorage`에 저장합니다. 사주 계산은 기존 코드가 맡고 API 키는 서버에만 둡니다. **로컬 구현과 검증은 완료했으며, 공개 배포는 아직 하지 않았습니다.**

## 계획 중인 다음 단계: Google 로그인과 결과 이력

참가자는 **Google 로그인 후에만 사주 해석을 이용**하고, **생성한 결과를 모두 계정별 데이터베이스 이력으로 저장**하기로 결정했습니다. 로그인·로그아웃은 Spec 007, 결과의 저장·목록·상세·삭제와 사용자별 접근 제한은 Spec 008에 정의합니다. 연결된 프로젝트에서 테이블 존재와 로그인 계정의 결과 저장·조회는 확인했으며, 계정 간 접근 정책 시험은 남아 있습니다. 기존 브라우저 저장 결과는 계정 데이터베이스에 자동 이관하지 않습니다.

## 추가 개선: 금전 조언

Spec 010에서 다섯 번째 분야인 `금전`을 추가합니다. 사주로 수익이나 재산을 예측하지 않고 소비·저축 습관을 돌아볼 질문과 작은 행동을 제안합니다. 이전 네 분야 결과는 보존하며 금전 조언이 없었던 결과임을 표시합니다.

Spec 011에서는 금전 분야에 일간이 극하는 오행(재성)이 연주의 천간에 나타나는 첫 연도를 `사주에서 금전 기회로 읽는 시기`로 표시합니다. 이는 전통 해석을 보여주는 참고 정보이며 실제 수입·수익·성공 시기를 예측하거나 보장하지 않습니다. 오늘 해볼 행동보다 앞에 두고, 현재 연도를 기준으로 계산하므로 과거 저장 결과를 열어도 새로 표시합니다.

Spec 012에서는 전체 화면의 글꼴을 강원랜드가 공개한 `하이원 원추리 제목체`로 바꿉니다. 얇게·보통·굵게 세 종류를 본문·영역 제목·페이지와 배너 제목에 차례로 사용해 내용의 위계를 표현하고, 화면 아래에 글꼴의 출처를 밝힙니다.

Spec 013에서는 밤하늘과 20% 반투명 박스 위의 글씨를 밝게 하고, 실제 흰색 카드 안의 글씨는 어둡게 유지해 배경에 따른 대비를 확보합니다.

Spec 014에서는 참가자가 지정한 두 번째 밤하늘 이미지를 `운의 흐름 살펴보기` 배너에만 사용합니다. 페이지 전체 배경은 유지하고, 배너의 흰 글씨가 이미지 위에서도 읽히도록 어두운 막을 더합니다.

Spec 015에서는 `나의 오행 분포`와 `분야별 조언` 제목을 운의 흐름 배너 제목과 같은 25px로 표시합니다. 본문과 요약 카드 제목의 크기는 유지합니다.

Spec 017에서는 운의 흐름 배너에 적용한 밤하늘 이미지를 50% 투명하게 표시합니다. 글씨와 연도 카드에는 투명도를 적용하지 않습니다.

Spec 019에서는 로그인한 사용자가 저장된 결과의 전용 링크를 만들어 공유할 수 있게 합니다. 공유 링크의 결과는 로그인 없이 읽을 수 있지만, 공유받은 사람이 자신의 사주를 생성하려면 Google 로그인을 해야 합니다. 출생일시 원문과 계정 정보는 공유하지 않습니다.

## 계획 중인 다음 단계: 매일 오늘의 운세

Spec 021에서는 로그인한 사용자별로 가장 최근에 저장된 사주 1건을 기준으로 오늘의 운세를 미리 생성합니다. 저장된 모든 과거 사주마다 만들지 않아 Gemini 호출 비용과 중복 결과를 줄입니다. 최근 사주가 없는 사용자는 생성 대상에서 제외하고 먼저 사주 해석을 만들도록 안내합니다.

오늘의 날짜와 간지는 기존 계산 코드가 한국 표준시 기준으로 정하고 Gemini에게 계산을 맡기지 않습니다. Gemini는 종합운·일/학업운·금전운·관계운·오늘의 행동을 자기 성찰용 문장으로 작성합니다. 질병·법률·재산·수익·합격·연애 등 미래 사건을 확정하거나 공포를 유발하는 표현은 허용하지 않으며, 응답 형식과 표현을 서버에서 검사한 뒤 저장합니다.

Vercel Hobby의 Cron이 지정된 한 시간 안에 실행될 수 있는 점을 고려해 매일 `21:00 UTC`에 작업을 예약합니다. 이는 한국 시간 오전 6시부터 6시 59분 사이이며, 오전 7시까지 운세를 준비하는 것을 목표로 합니다. Cron 엔드포인트는 `CRON_SECRET`으로 보호하고, 사용자 ID와 한국 날짜를 고유 기준으로 사용해 중복 호출에도 같은 운세가 두 번 생성되지 않게 합니다.

한 번의 실행에서 대상 사용자를 작은 묶음으로 처리하고, 사용자 한 명의 실패가 전체 작업을 중단시키지 않게 성공·실패 수를 기록합니다. Vercel이 실패한 Cron을 자동 재시도하지 않으므로, 생성되지 않은 사용자가 화면에 방문하면 그날의 운세를 다시 생성할 수 있게 합니다. 전체 사용자 수가 Hobby Function 실행 한도를 넘기기 시작하면 유료 플랜 또는 별도 작업 큐로 전환합니다.

오늘의 운세는 최근 30일만 보관합니다. 화면에서는 오늘 결과와 최근 결과를 조회할 수 있고, 30일이 지난 데이터는 예약 작업에서 정리합니다. 원본 출생일시, Gemini API 키, 인증 토큰은 오늘의 운세 테이블에 저장하지 않습니다.
